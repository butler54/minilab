# Phase 1 Data Model: Reduce Minilab CPU Usage

**Date**: 2026-10-09 · **Branch**: `010-reduce-cpu-usage`

All entities are configuration manifests rendered in Git and projected onto the
cluster — there is no mutable application data. Entities below capture owners,
fields, and state transitions that the plan must control.

## E1 — ArgoCD Cadence Overlay

Git-home: `values-global.yaml` → `main.gitops.customArgoYaml` (YAML string).

| Field | Value | Validation |
|-------|-------|------------|
| `extraConfig."timeout.reconciliation"` | `"600s"` | duration string; entity-level contract in `contracts/argocd-cadence-contract.md` |
| merge semantics | deep-merge with override over patterns-operator defaults | verified: `patterns-operator/internal/controller/argo.go` (`applyCustomArgoOverlayToSpec`) |

Propagation: `values-global.yaml` ─(`make operator-deploy` / pattern-install→Helm)→ ConfigMap `vp-gitops/patterns-operator-config` key `gitops.customArgoYaml` ─(patterns-operator)→ ArgoCD CR `vp-gitops` `spec.extraConfig` ─(gitops operator)→ argocd-cm.

Owner of the final object: openshift-gitops operator (writer), patterns-operator (spec generator), this repo (values truth). One writer per object — no conflict (D2 of research.md).

## E2 — Platform Monitoring Configuration

Manifest: ConfigMap `cluster-monitoring-config`, namespace `openshift-monitoring`
(pre-existing, currently empty; user-input object — CMO never reconciles it).

Git-home: `charts/openshift-monitoring-config/templates/configmap.yaml` rendered
by the new application entry `openshift-monitoring-config` in `values-prod.yaml`.

```yaml
data:
  config.yaml: |
    prometheusK8s:
      collectionProfile: minimal    # CMO-4.22-supported profile switch (research D3)
```

| Field | Value | Validation |
|-------|-------|------------|
| `prometheusK8s.collectionProfile` | `minimal` | enum {`full`(default),`minimal`} per CMO `PrometheusK8sConfig` |
| chart `values.yaml` stubs | `global`, `clusterGroup` empty maps | repo rule: standalone `helm template` must pass (`values.schema.json` enforced) |

State transitions: full → minimal (restarts prometheus-k8s-0 once; console dashboards + default platform alerts remain functional by API contract).

## E4 — Leaked Application Repair Record (imperative exception record)

Git-home: `scripts/repair-agent-sandbox-leak.sh` + `docs/agent-sandbox-repair.md`.

| Attribute | Value |
|-----------|-------|
| Trigger state | `Application/vp-gitops/agent-sandbox` exists AND not present in `values-prod.yaml` |
| Delete set | Application itself (foreground finalizer cascades): `Deployment/agent-sandbox-controller`, ClusterRole ×2, ClusterRoleBinding — exactly the 4 tracked resources |
| Preserve set | 4 `agents.x-k8s.io` CRDs (untracked by the leaked app), namespace `agent-sandbox-system`, OLM Subscription+CSV |
| Preconditions | zero `sandboxes`/`sandboxclaims` CRs; `oc whoami` has delete rights; cluster reachable |
| Postcondition signal | CSV `agent-sandbox-operator.v0.9.0` phase `Succeeded`; no `InstallComponentFailed` events |
| Idempotence | second run is a verified no-op (exit 0, "no leak present") |

## E5 — Operator Install (CSV) State Machine (observed, not modeled in Git)

Target segment of the failure loop the repair must leave behind:

```text
Failed ──(NeedsReinstall, hot loop ~6/s)──► Pending ──► (ImmutableSelector error) ──► Failed   [BEFORE]
Failed ──(repair removes foreign Deployment)──► Installing ──► Succeeded ──► stable            [AFTER]
```

Health proxy: absence of `Normal NeedsReinstall` + `Warning InstallComponentFailed`
events for `agent-sandbox-system/agent-sandbox-operator.v0.9.0` after repair; CSV
`status.phase == Succeeded` for ≥24h (SC-003).

## E6 — Evidence Record

Git-home: `specs/010-reduce-cpu-usage/ANALYSIS.md` (append-only).

Whatever runs a gate (G1–G6) appends: timestamped header, the exact probes run
(commands + the PromQL used in `ANALYSIS.md`), the observed numbers, and the
verdict vs. the SC threshold that gate measures. This satisfies FR-011 without
a second telemetry system.
