# Data Model: Bootstrap Local Storage

## Local Storage Configuration

| Field | Meaning | Validation |
|-------|---------|------------|
| `capacityGiB` | Usable capacity offered to PVCs | Positive integer; defaults to `100` |
| `backingFilePath` | Persistent host file used to create the loop device | Fixed approved path; must not be under a kubelet-managed volume path |
| `backingFileGiB` | Host allocation for the backing file | `ceil(capacityGiB / 0.85)`, rounded up to a 4 GiB boundary; 120 GiB at the default |
| `hostReserveGiB` | Space kept free on the `/var` filesystem after allocation | Fixed minimum of 20 GiB; bootstrap rejects smaller available capacity |
| `loopDevice` | Stable host block-device identity | Fixed value; must be unused or already map to `backingFilePath` |
| `storageClassName` | PVC class generated for the device class | Must equal the verified class generated by the selected LVMS release; claims above `capacityGiB` are rejected |

**Lifecycle**: Requested -> validated -> MachineConfig applied -> node configuration complete -> loop device attached -> LVMS ready -> storage class available. Any validation or readiness failure stops the transition and leaves Vault unavailable.

## Bootstrap State

| Field | Meaning | Validation |
|-------|---------|------------|
| `machineConfigApplied` | Git-tracked host configuration was accepted | Matching MachineConfig rendered successfully |
| `systemdUnitSucceeded` | Bootstrap unit created or reattached the device | Unit reports successful completion after node rollout |
| `loopMappingVerified` | Fixed loop device maps to the expected backing file | Exact path match required |
| `operatorReady` | LVMS controller and CRDs are usable | Operator deployment reports ready |
| `lvmClusterReady` | LVMS has configured the device class | LVMCluster reports ready |
| `storageClassReady` | Generated class can accept claims | Class exists with required binding and reclaim behavior |

**Lifecycle**: Unprepared -> bootstrapping -> ready -> failed. A failed state is diagnostic only; the bootstrap must not silently construct a replacement volume group.

## Vault Persistence Configuration

| Field | Meaning | Validation |
|-------|---------|------------|
| `defaultStorageClass` | Pattern-supplied class for Vault persistence | Set to the verified generated LVMS class |
| `operatorOverride` | Explicit alternative storage class | Takes precedence when non-empty and supported |
| `claimStatus` | Vault PVC lifecycle state | Vault is not considered ready until bound |

**Relationship**: One local-storage configuration produces one designated storage class. Vault selects that class by default; multiple workloads can request it explicitly.
